<task type="auto">
  <name>Task 1: Implement security middleware (rate limiter, payload limits, sanitized error handler)</name>
  <files>src/server/middleware/security.ts, src/server/index.ts</files>
  <action>
    1. Create `src/server/middleware/security.ts`:
       - `createRateLimiter(options: { maxRequests: number; windowMs: number })`:
         - Tracks request counts per client IP within a sliding or fixed time window.
         - If exceeded, returns HTTP 429 with `{ success: false, error: { code: 'RATE_LIMITED', message: 'Too many evaluation requests', statusCode: 429 } }`.
         - Adds `RateLimit-*` headers (limit, remaining, reset).
       - `securityHeadersMiddleware`:
         - Adds security headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Strict-Transport-Security`.
       - `sanitizedErrorHandler`:
         - Catches unhandled errors or payload too large errors.
         - If error is `entity.too.large`, returns HTTP 413 `{ success: false, error: { code: 'PAYLOAD_TOO_LARGE', ... } }`.
         - Ensures no secrets or stack traces are emitted in the response.
    2. Update `src/server/index.ts`:
       - Export `app` for testing (`export const app = express()`).
       - Apply payload limit: `express.json({ limit: '100kb' })`.
       - Apply `createRateLimiter({ maxRequests: 60, windowMs: 60000 })`.
       - Apply `sanitizedErrorHandler`.
  </action>
  <verify>npx tsx -e "import('./src/server/middleware/security.ts'); console.log('Security middleware valid');"</verify>
  <acceptance_criteria>
    - Rate limiter middleware tracks requests and returns 429 on overflow
    - Payloads > 100kb trigger PAYLOAD_TOO_LARGE
    - app is exported from src/server/index.ts
  </acceptance_criteria>
  <done>Security middleware implemented and wired into server</done>
</task>
